# ① Arithmetic Intensity: 읽고 쓴 데이터로 얼마나 계산할까?

> **한 줄 답.** 산술 강도는 이동한 1 Byte당 수행한 FLOPs다. 같은 계산량이라도 HBM에서 덜 읽고 쓰면 값이 커진다.

[4주차 목차](./README.md) · 다음 → [② Roofline](./02-roofline.md)

## 1. 정의와 세는 경계

$$
I = \frac{F}{Q}
=\frac{\text{총 FLOPs}}{\text{HBM에서 읽고 쓴 총 Byte}}
\quad[\mathrm{FLOPs/Byte}]
$$

산술 강도는 저장된 파일 크기나 할당한 메모리 용량으로 나누는 값이 아니다. 같은 원소를 HBM에서 10번 읽었다면 **10번의 이동량**을 센다. 입력 읽기뿐 아니라 출력 쓰기도 포함한다. 정의와 두 시간의 관계는 [Scaling Book 1장의 Arithmetic Intensity 설명](https://jax-ml.github.io/scaling-book/roofline/)을 참고한다.

이번 문서에서는 **HBM ↔ 칩 내부** 경계를 센다. Shared Memory에서 레지스터로 같은 값을 다시 읽는 것은 HBM 이동량 Q에 더하지 않는다. 그 온칩 이동도 실제로는 시간과 자원을 쓰지만 이번 Roofline에는 별도 상한으로 넣지 않는다. 따라서 I를 말할 때는 항상 어느 메모리 구간을 기준으로 삼았는지 밝혀야 한다.

## 2. Vector Add: 입력을 다시 쓸 곳이 없다

FP32 `C[i] = A[i] + B[i]`는 출력 하나당 덧셈 1회, 입력 2개 읽기와 출력 1개 쓰기다. 길이가 L이면 다음과 같다.

$$
F=L,\qquad Q=4L+4L+4L=12L,\qquad I=\frac{1}{12}\approx0.08333
$$

각 A·B 원소는 하나의 출력에만 쓰인다. 입력을 한 번씩 읽는 조건에서 벡터를 작은 구간으로 나누기만 해서는 Q가 줄지 않는다. [3주차 Vector Add 풀이](../week3/06-vector-add.md)의 시간 계산에 산술 강도라는 이름을 붙인 것이다.

## 3. MatMul: 같은 입력으로 여러 출력을 계산한다

$$
C[i,j]=\sum_{k=0}^{K-1}A[i,k]B[k,j]
$$

`A[i,k]`는 같은 행의 `C[i,0], …, C[i,N−1]`에, `B[k,j]`는 같은 열의 `C[0,j], …, C[M−1,j]`에 쓰인다. 수학적으로는 재사용 기회가 있지만, 값을 온칩에 유지하는 실행 방식이 있어야 HBM 읽기도 줄어든다.

정사각 행렬 한 변을 N, 출력 타일 한 변을 T라고 하자. 중간 합은 온칩에 두고 최종 C만 한 번 쓰는 조건이다.

| 계산 방식 | F (FLOPs) | Q (Byte) | I (FLOPs/Byte) |
|---|---:|---:|---:|
| Vector Add, 길이 L | L | 12L | 1/12 |
| MatMul, 입력 재사용 없음 | 2N³ | 8N³ + 4N² | N/(4N+2), 약 1/4 |
| MatMul, T×T 출력 타일 안에서 재사용 | 2N³ | 8N³/T + 4N² | NT/(4N+2T), N≫T이면 약 T/4 |
| MatMul, 전체 입력을 각각 한 번만 읽는 이상적 기준 | 2N³ | 12N² | N/6 |

마지막 행은 [3주차 MatMul](../week3/07-matmul.md)에서 사용한 낙관적인 기준이다. 이번 주의 **타일 사이 캐시 재사용 없음** 조건에서는 입력이 출력 타일마다 다시 필요하므로, 32·64·128 타일에 `12N² Byte`를 적용하면 안 된다. 타일별 공식은 [③ Tiling](./03-tiling.md)에서 직접 센다.

## 4. FLOPs가 같고 Byte만 줄면 무엇이 바뀔까?

F를 고정하고 Q를 절반으로 줄이면 I는 두 배가 되고, `Q/BW`는 절반으로 줄어든다. 하지만 `F/P`는 그대로다. 메모리 시간이 더 클 때는 시간 단축을 기대할 수 있고, 연산 시간이 더 커진 뒤에는 HBM 이동량 감소만으로 이상적 시간이 더 줄어들지 않는다.
