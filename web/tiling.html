03두 배 큰 타일, 네 배의 보관 공간

위에서 선택한 출력 타일을 보관하는 데 필요한 공간입니다. 입력 버퍼와 중간 합은 서로 다른 자원에 놓일 수 있습니다.

A·B 입력 한 벌 · 8T² B
중간 합 acc · 4T² B

막대 기준: 각각 128 KiB. 보통 입력은 Shared Memory, 중간 합은 스레드들에 분산된 레지스터에 둡니다. 두 값을 더해 Shared Memory 요구량이라고 부르면 안 됩니다.

출력은 64×64로 고정하고, K 폭만 바꾸면?

K=4096, TM=TN=64. 아래 실험은 위 선택과 독립적입니다.

입력 한 벌
K 단계 수
타일당 총 입력 읽기

4K(TM + TN) = 2 MiB로 일정합니다. K 폭이 두 배면 단계 수는 절반. 중간 합은 항상 16 KiB입니다.

큰 타일이 언제나 정답은 아닙니다

재사용이 늘면 메모리 이동은 줄지만, 블록 하나가 차지하는 공간도 커집니다. 같은 SM에 상주할 블록·warp 수가 줄어 지연을 숨길 기회가 감소할 수 있습니다.

Occupancy를 여기서 계산할 수 있을까요?

Occupancy는 ‘활성 상주 warp 수 ÷ 하드웨어 최대 warp 수’입니다. 이 모델은 P와 BW만 주므로 정확한 Occupancy나 타일의 실행 가능성은 알 수 없습니다. SM의 메모리·레지스터 용량, 스레드 배치 등의 조건이 더 필요합니다.

128×128 타일 = 16,384개 스레드?

출력 원소 수와 스레드 수는 다릅니다. 한 스레드가 여러 중간 합을 맡을 수 있습니다. 예를 들어 32×32 출력 1,024개를 256개 스레드가 나누면 스레드당 4개 출력입니다.

이 모델이 생략한 것은?

입력은 이미 GPU에 있습니다. 출력 타일 사이의 캐시 재사용, CPU 전송, 추가 이동·spill·padding·동기화 비용은 제외합니다. 중간 합은 온칩에 유지하고 최종 C만 한 번 씁니다. 연산과 이동이 충분히 겹친다고 가정합니다. 실제 성능은 이 상한보다 낮을 수 있습니다.

Local Blocking과 Shared Memory Blocking

Local Blocking은 한 스레드 안에서 여러 출력을 위해 입력을 재사용합니다. Shared Memory Blocking은 같은 블록의 스레드들이 입력 조각을 함께 가져와 공유합니다. 두 방식은 함께 사용할 수 있습니다.
